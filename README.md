# Telegram chip – агент работает с вашим аккаунтом Telegram

Telegram chip даёт AI-агенту (Claude Code, Codex, Hermes и другим) доступ к **вашему личному аккаунту Telegram**: читать чаты и группы, искать по переписке, отправлять сообщения и файлы в существующие диалоги, выгружать историю. Агент обращается к нему как к обычному API на вашем сервере.

Это отдельный репозиторий telegram-chip от AgentOS. Раньше скилл лежал внутри общего каталога [agentos-skills-public](https://github.com/qwwiwi/agentos-skills-public/tree/main/skills/telegram-chip). Та копия больше не обновляется, ставьте отсюда.

## Главное правило – первым не пишем

Аккаунт никогда не пишет первым незнакомому человеку. Отправка в личный чат, где человек ещё ни разу вам не написал, блокируется на уровне кода:

```
HTTP 403 {"success": false, "error": "no dialog: contact never wrote first – sending is forbidden (ban risk)"}
```

Telegram банит аккаунты за холодные сообщения. Группы, каналы и «Избранное» это правило не затрагивает. Не обходите его.

## Что умеет

- Чтение: список чатов и папок, сообщения чата, одно сообщение, поиск по сообщениям, участники и админы группы, статус пользователя.
- Медиа: скачать файл из сообщения, расшифровать голосовое (через Groq, по желанию).
- Отправка: сообщение, файл, пересылка, правка и удаление своих сообщений, черновики.
- Реакция: `POST /messages/react` ставит эмодзи (по умолчанию 🔥) на входящее сообщение в личном диалоге. В группах, ботах, «Избранном» и на свои сообщения реакция блокируется (HTTP 403/404), так же как отправка первым.
- Группы: создать группу или супергруппу, открыть историю новым участникам, пригласить, ссылка-приглашение, назначить админа, выйти.
- Порядок: архив, mute, папки, контакты.
- Защита от лимитов Telegram: автоматическое ожидание FLOOD_WAIT, паузы между запросами, лимиты на массовые действия ([RATE_LIMIT_PROTECTION.md](RATE_LIMIT_PROTECTION.md)).

## Око или Telegram chip

| | Око (бот-архив) | Telegram chip |
|---|---|---|
| Как работает | бот, которого вы добавляете в чат | вход в ваш личный аккаунт |
| Что видит | только чаты, куда добавлен, с момента добавления | все ваши чаты и всю историю |
| Пишет от вашего имени | нет | да, в существующие диалоги |
| Риск для аккаунта | нет | есть, если нарушать лимиты |
| Репозиторий | [oko-telegram-bot](https://github.com/qwwiwi/oko-telegram-bot) | этот |

Начните с Око, если агенту нужно только читать рабочие чаты. Chip – когда агент должен работать с личными переписками и писать сам.

## Установка

Нужен сервер с Python 3.11+ (лучше не в России: вход в Telegram с российских IP часто требует лишних проверок).

1. Получите `api_id` и `api_hash` на https://my.telegram.org – пошагово в разделе [«Как получить api_id и api_hash»](#как-получить-api_id-и-api_hash) ниже.
2. Склонируйте репозиторий и поставьте зависимости:

```bash
git clone https://github.com/qwwiwi/telegram-chip-public.git
cd telegram-chip-public
python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
cp .env.example .env   # впишите TELEGRAM_API_ID и TELEGRAM_API_HASH
```

3. Создайте сессию скриптом `./generate-session.sh` – подробно в разделе [«Как создать сессию»](#как-создать-сессию) ниже. Строка сессии попадёт в `.env` как `TELEGRAM_SESSION_STRING`.
4. Запустите API: `.venv/bin/python api.py` (порт `8080`), проверьте `curl http://127.0.0.1:8080/health`.
5. Держите API только на `127.0.0.1` или внутри Tailscale. Наружу в интернет не открывайте.

Docker и docker-compose в репозитории не предоставляются: запуск через обычный Python-venv, как выше. Если нужен автозапуск, оформите `.venv/bin/python api.py` как systemd-сервис или аналог на своём сервере.

Проще всего отдать это агенту: дайте ему ссылку на репозиторий и попросите поставить по README и [SKILL.md](SKILL.md). Код из Telegram и пароль вводите сами.

Подробная техническая документация на английском – [README-technical.md](README-technical.md).

## Как получить api_id и api_hash

`api_id` и `api_hash` – это ключи вашего приложения в Telegram. Без них вход в аккаунт через chip невозможен. Получаются бесплатно, один раз.

### Если вы в России

Сайт my.telegram.org нужно открывать **без VPN**, но из России он часто не открывается без него. Рабочие варианты:

- открыть сайт из-за границы (с компьютера или телефона, который находится не в России);
- либо открыть его через **статический резидентный прокси** (static residential / ISP proxy – IP-адрес выглядит как домашний, а не как адрес дата-центра).

Обычный VPN и прокси с IP из дата-центра почти наверняка не подойдут: страница не загрузится либо при создании приложения будет ошибка `ERROR`. Нужен именно резидентный IP.

### Шаги

1. Откройте https://my.telegram.org (по правилам выше).
2. Введите номер телефона в международном формате (с `+`) и нажмите «Next».
3. Код входа придёт **в приложение Telegram** (чат «Telegram»), а не по SMS. Введите его на сайте.
4. Откройте раздел **API development tools**.
5. Заполните форму создания приложения:
   - **App title** – любой текст, можно случайный, например своё название;
   - **Short name** – 5-32 символа, только латинские буквы и цифры, любой, можно случайный;
   - **URL** – впишите `www.google.com`;
   - **Platform** – `Web` (подойдёт и `Other`; `Desktop` тоже допустим);
   - **Description** – можно оставить пустым.
6. Нажмите **Create application**.
7. На открывшейся странице скопируйте **App api_id** (число) и **App api_hash** (строка из 32 символов).
8. Впишите их в `.env`: `TELEGRAM_API_ID=` и `TELEGRAM_API_HASH=`.

`api_hash` – секрет, как пароль. Не отправляйте его в чаты, не публикуйте в GitHub и не показывайте посторонним.

### Частые проблемы

- **При создании приложения появляется `ERROR`.** Самая частая причина – IP: сайт не любит VPN и адреса дата-центров. Откройте его с резидентного IP (см. «Если вы в России») или с мобильного интернета без VPN.
- Попробуйте другой браузер или новое окно инкогнито: бывают проблемы с кэшем и старой веб-сессией.
- Подождите и повторите позже: ошибка иногда проходит сама.
- Аккаунт, который только что зарегистрирован, может получить отказ. Используйте более старый аккаунт.
- Код не приходит: проверьте сообщения от чата «Telegram» в приложении, SMS не будет.
- Приложение уже создано: страница API development tools просто покажет существующие `api_id` и `api_hash`, создавать второе не нужно.

## Как создать сессию

Сессия – это строка, по которой chip заходит в ваш аккаунт без повторной авторизации. Создаётся один раз.

1. Убедитесь, что в `.env` уже вписаны `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` (см. выше).
2. Запустите в папке репозитория:

   ```bash
   ./generate-session.sh
   ```

   Скрипт сам создаст `.venv`, поставит зависимости и запустит генератор.
3. **Phone:** введите номер телефона в международном формате с `+` (код страны и номер), например `+<код_страны><номер>`.
4. **Enter login code from Telegram:** введите код, который пришёл в приложение Telegram на этом аккаунте.
5. **Enter 2FA password:** этот вопрос появится только если на аккаунте включён облачный пароль (двухфакторная защита). Введите его – при вводе символы не отображаются.
6. После слов «Authentication successful!» скрипт покажет строку сессии и спросит `Update local .env automatically? (y/N)`. Введите `y` – строка запишется в `.env` как `TELEGRAM_SESSION_STRING=...`. Если ответили `N`, скопируйте строку и впишите в `.env` вручную.
7. Проверьте, что в `.env` есть строка `TELEGRAM_SESSION_STRING=`, и запустите API (`.venv/bin/python api.py`).

Строка сессии даёт полный доступ к аккаунту. Не отправляйте её в чаты и не коммитьте `.env`. Одну строку используйте только в одном запущенном процессе, иначе Telegram разорвёт сессию (`AuthKeyDuplicatedError`).

## Безопасность

- Строка сессии = полный доступ к аккаунту. Храните её только в `.env` на сервере, не в чатах, не в GitHub, не в памяти агента.
- Если сессия утекла: Telegram → Настройки → Устройства → завершить сессию.
- Пропишите агенту в CLAUDE.md или AGENTS.md: работа с Telegram только через chip, соблюдать лимиты, первым не писать, массовые рассылки только с вашего согласия.
